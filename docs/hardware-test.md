# 实机测试前置条件与风险（1080p 64/60 Mbps）

> [English](hardware-test.en.md) | 中文

**结论（2026-11-06）**：容器链路已经可以逐字节复现，但**没有任何一台 D750
实机验证过更新器接受度或编码器行为**。当前定位是“有备用机兜底的高风险实验”，
不是可以推荐的刷机流程。

QEMU M0 只覆盖启动入口，**对 H.264 编码器、写卡、回放没有预测力**；不要把
M0 通过当成实机可用的证据。

## 1. 已经验证的（容器层）

输入：stock `D750_0115.bin`（21,552,187 B）与改后 `b1010_115a.bin`。
工具：同作者仓库
[Nikon-Expeed-4-and-5-firmware-tool](https://github.com/LuoStickmin/Nikon-Expeed-4-and-5-firmware-tool)
中的 `repack_firmware.py` 与 `d750_bitrate_verify.py`。

- D750 使用**包装 A**：`0x00` 起 32 个空格，文件里没有 20 字节带密钥摘要；
  K8/`STALE` 只影响包装 B（D850/D5 那类），与 D750 无关。
- 无修改重打包 stock：`--selftest` 输出与输入 **bit-identical**
  （sha256 `6c1dfadc8feb38bc783522c37f6351e1e8006f4684c8234690afb9aa08444859`）。
- stock + 改后 `b1010` 模块重打包：输出与 `bitrate/README.md` 记录的
  `9c88f3cc80e5e19d780055ced0e4e539739f0e858af1e831228e5f19e904988a`
  **逐字节一致**。
- 容器差异：同大小；文件头 32 B 不变；仅 **36 B** 不同，位置为
  `0x3D6575..0x3D665C`（5 个 HQ 行）与 `0x148DC29..2A`（b1010 模块 CRC）；
  包 CRC 字段 `0x148DC2B` 保持 `f540`（residue）；另外两个模块逐字节相同。

这证明“改表 → 重算 CRC → 重加密 → 容器”这条链路可复现，**不**证明相机端。

## 2. 没有验证的（决定实机成败）

| 项目 | 现状 | 为什么重要 |
| --- | --- | --- |
| 更新器接受度 | ❓ 无实机记录 | 可能因型号/版本/隐藏校验拒绝，或要求“更高版本” |
| 同版本重刷 | ❓ 未知 | 1.15 → 1.15 若被拒，不能靠改版本号硬绕（风险升级） |
| 编码器行为 | ❓ 未知 | 表内上限 70,780,800 支持 64 Mbps，但 D750 编码器可能另有上限/降码率 |
| 写卡/缓冲/发热 | ❓ 未知 | 64 Mbps ≈ 8 MB/s，慢卡、长时间录制、散热都可能出问题 |
| 回放兼容 | ❓ 未知 | 可能出现电脑能播、机内不能回放 |
| 失败模式 | ❓ 未知 | 拒绝（安全）／更新中断／启动失败（需送修） |

## 3. 上机前的硬门槛（缺一不刷）

1. **有备用 D750**，或能承担换主板/送修成本。
2. **自己重跑一遍链路**，不要只信本文的数字：

   ```sh
   # 1) 无修改重打包，必须 bit-identical
   python repack_firmware.py --firmware D750_0115.bin --key key_all.json \
     --out stock.repack.bin --selftest
   # 2) stock + 改后模块，必须得到 9c88f3cc…
   python repack_firmware.py --firmware D750_0115.bin --key key_all.json \
     --out D750_0115.hq64.bin \
     --replace-module b1010_115a.bin=b1010_115a.hq64.bin --encrypt --keep-tags
   ```

3. **静态检查更新器**：确认它只做 CRC/型号/版本检查，还是另有隐藏验签。
   这是零风险、信息量最大的一步。
4. **确认同版本策略**：如果 1.15 → 1.15 不被接受，先停下来评估，不要改版本号
   硬刷。
5. **准备回刷**：stock 镜像、满电或假电池、已知良好的 UHS-I 卡；改后文件必须
   改名回 `D750_0115.bin`（放在卡上让相机识别）。

## 4. 最小风险流程

1. 更新器接受 → 开机检查版本与基本功能（拍照/回放/菜单）；
2. 录 10 秒 1080p HQ → `ffprobe` 看实际码率是否接近 64 Mbps；
3. 机内回放这段文件；
4. 摸机身温度、确认没有停录/花屏；
5. 逐步加长：30 秒 → 2 分钟 → 更长；
6. 任何异常立即停止；**不要连续刷第二次**。

## 5. 判据

- **成功**：码率接近 64 Mbps、机内可回放、无停录/过热、长时间稳定。
- **可接受的失败**：更新器拒绝（通常未写入，机器仍是 stock）。
- **需送修**：黑屏、无法开机、更新中断。

## 6. 记录要求

- 相机型号/当前固件版本、文件名、镜像 SHA-256、模块 SHA-256；
- 更新器的提示/错误码；
- `ffprobe` 输出、录制时长、温度、卡型号；
- 结果回填到本仓库的 issue/PR（**不要附固件或改后镜像**）。

## 7. 不做的事

- 不提供刷机包、密钥、解密器或改后镜像；
- 不绕过验签，不提供“防砖”承诺；
- 不承诺任何机型/固件版本的兼容性。
