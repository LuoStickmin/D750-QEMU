Same Cortex-M reset address as the D750 a1010 and D850 a1330 modules.

The reset target 0x102FE368 (file 0x2FE368) is itself a branch table:

  102fe368  b 0x102fe654
  102fe36c  b 0x102fe67c   (x6)
  102fe384  b 0x102fe6a4   (x5)

The exception vectors point at 0x4002xxxx, i.e. the same separate
0x40000000 boot-ROM / handler bank seen in the D850 (E5) image.

b870 contains 7178 occurrences of the literal 0x40000000.

"Boot" strings in b870 are runtime power/reboot command names, not boot code:

  eSyscController_BootShutDown
  eSyscCommandId_PowerOnBoot
  eSyscCommandId_InitializeFastBoot
  "SYSTEM REBOOT"
  SYS_BOOT_BUS_CLK / SYS_BOOT_BTSQ_CLK

No "bootloader"/"bootstrap"/"mask rom" strings, and no small module with a
second-stage boot image.

Conclusion
----------
The D5 firmware image does NOT contain a boot ROM or a bootloader module.
Like D750 (E4), D850 (E5) and D780 (E6), it ships the M-core firmware plus the
main application (and wireless/config modules); the A-core boot/first-stage
code is expected to live in the separate 0x40000000 boot-ROM region.
