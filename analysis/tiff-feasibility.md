# D750 拍摄菜单加入 TIF 存储选项：可行性分析

> [English](tiff-feasibility.en.md) | 中文

日期：2026-11-05  
对象：Nikon D750，固件 `D750_0115`，主模块 `b1010_115a.bin`（20,324,448 B，SHA-256
`faada7fe…f82937fd`）  
性质：**只读静态分析；没有修改、重打包或刷入任何固件。**

## 结论

**不能靠“打开一个开关”在 D750 的拍摄菜单里复现 TIF 存储。** D750 固件里确实有
TIFF 相关字节，但它们是：

1. 通用的**文件名模板**（`DSC_0000.TIF`）；
2. **XMP/EXIF 元数据解析**用的扩展名和 TIFF 标签表；
3. 代码字节或 JPEG 熵数据里的巧合字符串。

D750 没有 TIFF 图像**编码器**，也没有任何语言的 `TIFF`/`TIF` 菜单文本。真正支持
`TIFF (RGB)` 的是 D810、D850、D5 这一档机型；D750 的固件里连标签都没有。要在
D750 上加入 TIF 拍摄，等于新写一个 TIFF 编码器并接入静态图像管线、菜单、设置持久化
和回放/DPOF，属于功能移植，不是静态补丁。

因此本次**没有修改固件**。下面给出证据、边界和如果要继续做所需的工程步骤。

---

## 1. 固件里实际找到的 TIF 字节

对 `b1010_115a.bin` 做 ASCII/UTF-16 全量扫描，真正的 TIF 命中只有以下几类：

| 偏移 | 内容 | 性质 |
| --- | --- | --- |
| `0x126b4b6` | `DSC_0000.TIF` | 文件名模板表，和 `DSC_0000.NDF/NEF/JPG` 并列 |
| `0x1bf9ec`/`0x1bf9f0` | `JPG\0TIF\0` | XMP 元数据解析器的扩展名表 |
| `0x11edf40` 起 | TIFF/EXIF 标签与文件解析表 | 读元数据/文件结构，不是像素编码器 |

其余命中都是误报：

- `0x22c9cf` 的 `TIF` 落在 Thumb 代码字节中（非字符串）；
- `0x34c536`、`0x3a90d8` 的 `TifO` 落在 JPEG 熵编码数据里；
- `0x23de04`、`0xe83d44` 等是 `notify…` 单词里的 `tif` 子串。

### 1.1 `DSC_0000.TIF` 是平台通用模板

这个字符串在 D810、D850、D5 的固件里同样存在（D810 `0x1148f86`、D850
`0x1782618`、D5 `0x15e7010`），而 D810/D850/D5 是支持 `TIFF (RGB)` 的。它说明
EXPEED 平台的 DCF 文件名表保留了 `.TIF` 扩展名，**不说明当前机型能写 TIFF**。
D750 的拍摄菜单只使用 NEF/JPG 两个扩展名。

### 1.2 `JPG/TIF` 属于 XMP 解析器

`0x1bf9ec` 附近紧跟着 `-ATR DTM`、`../DCIM/`、`A:\MISC`，再往后是
`dc.Source`、`photoshop`、`Iptc4xmpExt`、`CaptionWriter` 等 XMP 字段。这是
**读 XMP/元数据**的扩展名与字段表，和“拍一张 TIFF”没有关系。

### 1.3 TIFF 标签表是 EXIF/NEF 元数据框架

`0x11edf40` 开始的表包含 `II*\0` / `MM\0*` 文件和大量 TIFF/EXIF 标签
（`0x0100`、`0x0101`、`0x0103`、`0x0106`、`0x0111`、`0x0115`、`0x0116`、
`0x0117`、`0x8769`、`0x8825`、`0x9000`、`0x9003`…）。相机读写 JPEG/NEF 的
EXIF 必须用这套框架；它处理的是**元数据 IFD**，不是把 8-bit RGB 像素写成 TIFF
图像。D810 里也有同样的表，而且 `II*\0` 字面量同样只出现一次，所以它不能作为
“TIFF 编码器存在”的证据。

---

## 2. 菜单层证据

### 2.1 D750 没有任何 TIFF 菜单文本

对四个模块做 UTF-16LE 扫描（`tiff_scan.py`）：

```
D750 b1010_115a   UTF16 'TIFF'=0    'TIF'=0    'JPEG/TIFF'=0
D810 b920_114     UTF16 'TIFF'=180  'TIF'=180  'JPEG/TIFF'=35
D850 b1330_131    UTF16 'TIFF'=144  'TIF'=144  'JPEG/TIFF'=36
D5   b870_150     UTF16 'TIFF'=144  'TIF'=144  'JPEG/TIFF'=36
```

D750 在所有 36 种语言的字符串池里都没有 `TIFF`/`TIF`，也没有
`TIFF (RGB)`、`TIFF(RGB)`、`JPEG/TIFF` 或 TIFF 帮助文本。D810、D850、D5 都有
完整的菜单和帮助文本（例如 D810 英文 `0x6b48d6`，D850 英文 `0xcf2ab0`）。

### 2.2 D750 图像质量菜单只有 7 项

英文菜单组在 `0x756cc8`（日文组在 `0x73c2f2`），内容是：

```
NEF (RAW) + JPEG fine
NEF (RAW) + JPEG normal
NEF (RAW) + JPEG basic
NEF (RAW)
JPEG fine
JPEG normal
JPEG basic
```

没有第 8 项。菜单文本是**按语言打包的连续 UTF-16 池**（没有 NUL 分隔），靠偏移表
指向每个标签；插入一个新标签会改变它后面所有标签的偏移，36 种语言都要重排。这不是
改一个字节能完成的。

---

## 3. 为什么不能“打开开关”

| 层 | D750 现状 | 要加入 TIF 需要做什么 |
| --- | --- | --- |
| 菜单 | 7 项，无 TIFF 文本 | 在 36 个语言池插入标签并重排偏移；扩展菜单枚举 |
| 设置 | 图像质量枚举只有 NEF/JPEG 组合 | 新枚举值、默认值、NVRAM/配置持久化 |
| 拍摄管线 | JPEG 编码 + NEF 写入 | 取得 8-bit RGB 缓冲；写 TIFF 头、IFD、Strip/压缩、EXIF |
| 文件系统 | `.TIF` 模板存在但无写入路径 | DCF 文件名、目录项、回放/DPOF/缩略图 |
| 验证 | QEMU 原型只到 M0，不模拟 UI/ISP | 必须真机验证；没有真机时无法证明不会刷坏 |

关键是**编码器**：D750 的静态图输出是 JPEG（JFIF）和 NEF（TIFF 结构的 RAW），
没有“把 RGB 像素编码为 TIFF”的函数。即使把菜单项做出来，按下快门也没有东西可写。

D810 是同一代 EXPEED 4 且支持 `TIFF (RGB)`，理论上可以作为移植参考；但 D810 与
D750 的固件布局、图像管线、菜单数据和硬件都不同，不能把 D810 的代码块直接搬到
D750。移植至少需要：定位 D810 的 TIFF 编码器和调用点、找到 D750 对应的 RGB 缓冲和
保存路径、重做菜单/设置/回放、最后真机验证。工作量是“功能开发”，不是“补丁”。

---

## 4. 建议

1. **不要刷入**任何为了 TIF 而改的镜像；当前没有真机验证条件，风险远大于收益。
2. 如果只是要 TIFF 文件：D750 拍 NEF/JPEG，电脑端用 dcraw/ImageMagick/
   Lightroom/Capture NX 转 TIFF，质量比机内 8-bit TIFF 更好。
3. 如果确实要做机内 TIFF：先以 D810 的 `TIFF (RGB)` 路径做只读逆向，产出
   “编码器地址 + 调用约定 + D750 对应函数”的移植方案，再谈改固件；不要直接生成
   刷机镜像。

## 5. 复现方式

脚本：`analysis/tiff_scan.py`（只读，不修改固件）

```powershell
python analysis\tiff_scan.py --quality-group
```

它会输出四个模块的 UTF-16 `TIFF`/`TIF`/`JPEG/TIFF` 计数、D750 的 7 项图像质量
菜单，以及所有 ASCII TIF 字符串及偏移。

---

## 6. 边界

- 本文是静态分析结论，不是对相机行为的实测。
- “没有找到 TIFF 编码器”是基于字符串、菜单、标签表和代码布局的证据，不是对
  20 MB 固件的逐指令形式化证明；但足以否定“改一个开关就能启用”的说法。
- 固件版权属于 Nikon；本文不包含固件二进制，只记录偏移和结论。
